## What this release is about

A same-day fix for 2.10.0. After upgrading, some replies and forwards would not send: the analyst saw an error and the customer received nothing. It happened when the quoted thread underneath contained a picture from an earlier email on the ticket - and a logo in someone's email signature counts - so on some installs it was most replies. Everything else sent normally, which made it look random. Reported in [#158](https://github.com/edmozley/freeitsm/issues/158) by An Duong, who found the cause and tested a fix before reporting it.

**Fixes a problem present in 2.10.0 only.** If you are on 2.10.0, upgrade. Earlier versions are not affected.

## Fixes

- **Some replies and forwards failed to send.** If the quoted thread held a picture from the ticket, sending failed on every kind of mailbox - Microsoft 365, Gmail and SMTP - and the server log showed `Undefined constant "INLINE_THREAD_BUDGET"`. These now send, with the thread's pictures showing as pictures, as 2.10.0 intended. If a single picture ever cannot be added to an email, that picture now stays a link and the email still goes.

Replies that failed were not sent and were not saved on the ticket. The analyst was told at the time, but if one was never retried, that customer is still waiting for it.

## Upgrading

1. Pull the new code, or rebuild the Docker image.
2. Sign in as an administrator and run **System → Database Verification**. Nothing changes in the database this time, but it is a good habit.
3. Hard-refresh your browser (Ctrl-F5).

**Cannot upgrade straight away?** The fix is one line. In `api/tickets/send_email.php`, move `const INLINE_THREAD_BUDGET = 2 * 1024 * 1024;` up to just below the `require_once` lines near the top of the file.

## Rollback

Safe - nothing was removed from the database, so you can go back to 2.10.0 with the code alone. Going back brings this problem back.
